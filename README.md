# 壁纸盒子 · 官方壁纸库

程序仓库：[whoarei/wallpaper-box](https://github.com/whoarei/wallpaper-box)。本仓库只发布壁纸内容，面向壁纸盒子 0.2.0 及后续版本。

稳定目录入口：

```text
https://github.com/whoarei/wallpapers/releases/latest/download/catalog.json
```

程序匿名读取公开清单；用户无需 GitHub 登录。检查更新时只获取 `catalog.json`。每张壁纸都有独立 ZIP，用户点击哪张，就只下载或更新对应的一个包；已安装的壁纸离线也能运行。清单包含独立版本、最低程序版本、ZIP 下载地址、字节数与 SHA-256。程序下载、校验并在临时目录解压，完成验证后才激活新版本，保留上一版本以供回退。

## 添加壁纸

当前壁纸包括：静水之间、松风镇、通往别处的窗户、像素露营地、深空观测站、雨夜列车、云端浮岛、蔚蓝漫游、此刻星空和蓝色失重。新增内容仍独立打包，浏览目录不自动下载整库。

「蓝色失重」使用原创暮色泳池绘景和完整绘制的成年卡通女泳者，在宽 9000 个场景单位的泳池中完成 112 秒的完整旅程。界面静置后自动淡出；空格暂停，`A` 跟随人物，`1—7` 切换章节，`G` 开关鱼群和水草，`S` 隐藏界面，`R` 重新开始，`F` 全屏。独立预览支持拖动、滚轮与方向键探索，轻点池水泛起涟漪。桌面空白单击转发依赖主程序 0.2.1 起；长按拖动在独立预览中使用。三档速度与花园开关保存在当前 WebView，全部素材均随 ZIP 提供，运行时没有联网请求。动画上限 30 FPS；暂停及后台停止绘制，系统减少动态效果模式默认暂停。

从蓝色失重 1.1.0 起，人物的五官、发型、泳衣、完整身材与七种姿态统一重绘，以完整原画配合连续网格做柔和的插画动画。脸部、手指和脚趾设为保形区域；运动幅度自动限制在网格不折叠的范围内。泳镜统一位于额头，站立脚底对齐池沿，上岸过程中按池壁遮挡腿部。窄屏下适当缩小人物并调整镜头，保留完整的手脚轮廓。设备不支持 WebGL 时使用完整原画，保留角色巡游、场景与互动。

从蓝色失重 1.1.1 起，自由泳、蛙泳、仰泳、蝶泳各使用 16 个完整姿态，以同一身体位置对齐后循环播放，不把四肢拆开或把两个人物交叉淡化。自由泳增加低头与侧转换气；蛙泳在收腿、蹬夹后保留滑行；仰泳交替回臂；蝶泳同步划臂并配合两次打腿。身体起伏、前进速度变化和入水飞溅随各自的动作周期变化。泳姿序列使用 Canvas 2D，设备不支持 WebGL 时也能播放；某张动作图集加载失败时，回退到该泳姿原有完整原画。

蓝色失重验证：`node tests/blue-weightless.test.cjs` 检查完整轨迹、四个 16 帧周期、滑行时长、五官与手足保形、网格不折叠和落地位置；`node tests/blue-weightless.browser.cjs --browser <Chromium 路径>` 使用离线虚拟来源检查全部 64 个泳姿画面、章节、互动、循环、GPU 回退、多屏幕构图和动作图集缺失回退。加 `--motion-review` 可输出四组逐帧审阅图。设置 `WALLPAPER_ROOT` 可对解压后的正式包运行同一浏览器检查。

「蔚蓝漫游」的海底世界宽 7200 个场景单位。自动镜头先停留 14 秒，再平滑缓移，各海域之间停留 18 秒，往返巡游。拖动或按方向键进入自由漫游；`1 / 2 / 3` 前往不同海域，`A` 恢复自动巡游，空格暂停，`S` 隐藏界面，`F` 全屏，`H` 查看说明。系统启用减少动态效果时默认关闭自动镜头。场景完全离线运行，动画上限 30 FPS，后台自动停止绘制。

从蔚蓝漫游 1.1.0 起，轻点海水会绽开荧光涟漪与气泡，附近鱼群、珊瑚和海草随局部水流轻摆，鱼儿随后靠近微光再游回原来的路线。独立预览中按住约 1.6 秒再松开可释放更饱满的掌心星海，也可点击「✧ 唤起星海」或按 `E`。触碰深海水母，会依距离延迟点亮邻近水母。桌面端的空白处单击转发需要主程序 0.2.1 起；长按和拖动在独立预览中使用。所有互动随海底时间暂停，约十秒自然消退，并限制同时存在的粒子和涟漪数量。减少动态效果模式保留柔光与水母反馈，关闭扩散光环、追光游动和水流推移。

从蔚蓝漫游 1.2.0 起，直接轻点小鱼、海龟、鳐鱼或水母会使它们朝远离触点的方向游开，附近小鱼也轻微避让；随后逐渐恢复巡游。受惊期间优先逃离，并暂时忽略追光，避免刚游开又被同一次光效吸回来。水母避让时仍会点亮同伴。动物触碰与海水光效按实际画面位置区分，拖动不触发逃离；减少动态效果模式使用短距离的柔和避让。

「此刻星空」使用本地 Hipparcos 星表，依据 UTC、观测经纬度、恒星时与 J2000 岁差计算地平坐标，默认天顶居中、北上东左，白天也保留星图。首次为明确标注的上海示例位置；单击右上角可选择城市，桌面城市选择依赖主程序 0.2.1 起的空白处单击转发。独立预览支持主动设备定位、手动经纬度、球面拖动、滚轮缩放、全天视野及 60× / 600× 时间加速。桌面不接管拖动和滚轮。正常实时模式每秒重绘一次，后台停止绘制，恢复后同步当前天空。

桌面和预览的 WebView 存储区独立：在桌面选择城市会直接保存在桌面自己的存储区；如需将预览中设置的精确位置带到桌面，点击「保存此位置的桌面壁纸」，再从主程序设置导入生成的 ZIP。该包包含位置与显示偏好，不包含加速或暂停状态；位置不会上传。数据来源、BSD-3-Clause 许可及精度范围见 `wallpapers/zenith-sky/NOTICE.txt`。

复制一个目录到 `wallpapers/<id>/`，包含 `index.html` 和 `module.json`，图片、脚本、字体都使用相对路径。像素、Canvas 和 WebGL 场景都按同一规范运行。

```json
{
  "schemaVersion": 1,
  "id": "my-wallpaper",
  "type": "web",
  "name": "我的壁纸",
  "version": "1.0.0",
  "minAppVersion": "0.2.0",
  "entry": "index.html",
  "cover": "cover.jpg",
  "description": "壁纸说明",
  "tags": ["像素"]
}
```

## 发布内容更新

仓库提供两个可独立调用的 agent skill：

- [`wallpaper-release`](.agents/skills/wallpaper-release/SKILL.md)：用户明确要求准备或发布新版时使用。先列出更新点、推荐版本号与其他合理选项，由用户最终确定版本号后再修改版本、打标签发布。
- [`gitee-release-sync`](.agents/skills/gitee-release-sync/SKILL.md)：用户明确要求同步已发布版本、补齐 Gitee 漏传附件，或已授权的新版发布进入同步阶段时使用。复用原版本和原包，不另发内容版本。

普通开发、测试、提交和推送不调用这两个 skill，也不因此询问或修改版本号。仅同步 Git 源码时，按源码同步处理，不触发 Release 同步。

发布新版会衔接 Gitee 同步；两端完整校验且默认入口返回最新版后，才报告完整发布。独立验收命令为 `python scripts/verify_release.py library-vX.Y.Z`；只检查历史版时加 `--historical`，不要求旧版成为 latest。

1. 修改或加入壁纸；修改文件时增加该壁纸 `module.json` 的 `version`。
2. 增加 `library.json` 的库版本；壁纸版本和库版本独立。
3. 运行 `python scripts/build.py` 检查清单与 ZIP。
4. 提交后推送 `library-vX.Y.Z` 标签，版本须与 `library.json` 一致。
5. GitHub Actions 生成 ZIP、封面、catalog.json 和 SHA256SUMS.txt，再发布 Release。稳定入口随最新正式 Release 更新。
6. GitHub Release 发布成功后，自动将同名标签和 Release 附件同步到 [Gitee 壁纸库](https://gitee.com/xishuaiya/wallpapers/releases)。

主分支和 PR 只验证，不自动发布。已有正式 Release 不覆盖。相同壁纸版本不允许改变包内容；程序版本不兼容的条目会提示升级程序。

### 配置 Gitee Release 同步

在 Gitee 的个人设置 → 私人令牌中创建令牌，勾选 `projects` 权限，账号须有 `xishuaiya/wallpapers` 仓库的写权限。在 GitHub 仓库 **Settings → Secrets and variables → Actions → New repository secret** 添加 `GITEE_TOKEN`，值为该令牌；不要把令牌提交到代码中。

`.github/workflows/sync-gitee.yml` 会下载已发布的 GitHub Release 附件并校验 SHA-256，再推送该版本的 Git 标签、创建同名 Gitee Release。ZIP 和封面保持原始内容；Gitee 的 `catalog.json` 中下载和封面地址改为实际的 Gitee 附件地址，`SHA256SUMS.txt` 随之重新生成。上传后会匿名下载每个附件验证 SHA-256，全部完成后将 Gitee `main` 快进到本次检出的 GitHub `main`。主分支或标签存在冲突时不强制覆盖。

附件通过系统 `curl` 流式上传，令牌仅经标准输入传入。网络中断会先重新查询远端文件名并校验内容，再决定是否重试，避免请求已成功但响应丢失时重复上传。单次上传允许最长十分钟，每个文件最多尝试三次；某个附件的连接失败不会阻断其余附件的补传。清单和校验文件只在全部壁纸包与封面通过验证后上传；未完成的 Gitee 镜像标为预发布，完成后转为正式版本。失败日志保留 HTTP / curl 错误码，不输出令牌。

发布工作流成功后会直接调用同步流程，因为使用 `GITHUB_TOKEN` 发布 Release 不会触发另一个 `release: published` 工作流。同时保留 `release: published` 入口，支持手动在 GitHub 发布的正式版本。

补同步已有版本：打开 GitHub **Actions → Sync release to Gitee → Run workflow**，选择 `main` 分支，填写 `library-vX.Y.Z`；留空则取最新正式 Release。同步失败不会撤回 GitHub Release。修复同步脚本后应从 `main` 手动补同步，以使用新脚本；直接重跑旧标签的失败任务仍会使用旧版脚本。已有且校验一致的 Gitee 附件会复用；同名附件内容不一致或已有标签指向不同提交时会报错，不强制覆盖。GitHub 草稿和预发布版本不参与同步。

Gitee Release 入口：

```text
https://gitee.com/xishuaiya/wallpapers/releases
```

程序若要切换到 Gitee 更新源，需要读取 Gitee Release 中 `catalog.json` 附件的实际下载地址；GitHub 的稳定目录入口保持原样。

当前规范仅支持网页壁纸；不允许 ZIP 路径穿越、符号链接或 Windows 保留文件名。壁纸包不携带可调用程序管理命令的权限。
