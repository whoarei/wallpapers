# 给矩阵回声添加诗词

个人使用可在主程序 v0.12.0+ 的「壁纸设置 → 矩阵回声 → 诗词库」添加或导入下述 JSON，
先保存到草稿，再「保存到主程序」，各屏幕和预览共享。完整配置最多 32 KiB（UTF-8），
超限时页面保留草稿并提示精简。旧版宿主和普通浏览器仍在预览管理；原有本地作品
可导出 JSON 再导入新设置页。以下方式用于随官方内容包发布。

每首作品一个 UTF-8 `.json` 文件。可以直接在 GitHub 网页中点击
**Add file → Create new file**，放进当前目录，提交到下次发布使用的分支。
打包程序自动扫描此目录；无需改 JS、登记文件名或手动更新生成文件。

例如新增 `jing-ye-si.json`：

```json
{
  "title": "静夜思",
  "author": "李白",
  "dynasty": "唐",
  "verses": [
    "床前明月光，疑是地上霜。",
    "举头望明月，低头思故乡。"
  ]
}
```

- `title`：篇名，必填，最多 80 字。
- `author`：作者，必填，最多 40 字。
- `dynasty`：朝代，选填，最多 20 字。
- `verses`：1–128 个字符串，每个条目是一次完整展示的句子或句联，
  保留标点，每条最多 120 字。整句按原文顺序嵌入字节流，长句按从右向左
  的竖排顺序分到相邻字符列，随代码雨流过画面后再轮换。
- `id`：选填，1–64 位小写字母、数字或连字符。未提供时按篇名和作者
  自动生成稳定 ID。修改篇名或作者又希望保留原 ID 时，使用管理面板
  导出的文件，或从 `poems.generated.js` 查询 ID 后填入。
- `enabled`：选填，布尔值，默认 `true`。

不要把一首作品的各联拆到多个文件，也不要在多个文件中使用同一个 ID。
文件格式、必填内容、长度或 ID 有误时，构建会报出文件名和相关字段，
并停止打包。目录最多 500 首作品；单个文件最多 2 MiB。

## 从管理面板提交

在壁纸预览中打开「诗词与文字」，添加或编辑作品，再点击
「导出仓库文件 ZIP」。解压后把 `content/poems/` 中的文件放到本目录。
内置作品保留原文件名，可以直接替换；新增作品自动以稳定 ID 命名。
删除作品需要从仓库移除相应 JSON；导出的 ZIP 不会替你删除仓库文件。

「导出 JSON」导出整库数组，用于本地备份与批量导入。
提交仓库请使用「导出仓库文件 ZIP」，保持每个文件一首作品的结构。

## 本地预览与发布

在仓库根目录执行：

```sh
python scripts/sync_matrix_poetry.py
python -m http.server 8000 --directory wallpapers/matrix-echo
```

打开 `http://localhost:8000`。同步命令只用于刷新源码预览数据。
`python scripts/build.py` 每次都会从 JSON 重新生成 ZIP 中的
`poems.generated.js`，即使 GitHub 提交只包含一个新增 JSON 文件，
下次发布的包仍会带上它。之后按壁纸库既有流程更新版本并发布。
